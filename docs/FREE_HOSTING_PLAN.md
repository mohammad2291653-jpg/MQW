The runtime role is created NOLOGIN/NOBYPASSRLS, without administrative privileges. The operator privately assigns its login password separately. All runtime tables enable and force RLS. Owner records, idempotency receipts and audio are constrained by transaction-local `mqw.user_id` established from the verified opaque session. Auth/session/setup/cleanup tables permit only the trusted backend role's pre-authentication operations. This is the actual custom-cookie access model; it does not use `auth.uid()` or Supabase JWTs. PUBLIC, anon, authenticated and service_role receive no private-schema/table access.

The repository acquires one PostgreSQL client, begins a transaction, establishes verified owner context with transaction-local `set_config`, serializes transitions with a transaction-scoped advisory lock, awaits operations, and commits or rolls back before releasing the client. Local SQLite operations also serialize awaited callbacks. Set `MQW_STORAGE_BACKEND=postgres` explicitly on the free host so a missing database secret fails closed instead of silently falling back to ephemeral SQLite. `MQW_DATABASE_URL` remains a server-only secret, with verified TLS and an optional configured CA certificate.
